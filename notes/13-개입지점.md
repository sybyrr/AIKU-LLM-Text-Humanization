## 1. 프롬프트 개입 (생성 전)

**작동**: 생성 지시문만 바꿈. 모델도 디코딩도 안 건드림.

**하위 종류**

- **단순 지시** — "인간처럼 써라". 거의 효과 없음. baseline으로만 의미
- **가이드북 주입** — 회피할 특징 목록을 프롬프트에 넣음. Russell 방식. 사람 전문가 설명에서 목록을 뽑음
- **few-shot 인간 예시** — 같은 매체·장르의 인간 글을 예시로 붙임. Russell도 병행
- **자동 최적화** — SICO. 인간 글 40개로 in-context 예시를 반복 치환하며 최적화. 탐지기 AUC 평균 0.54 하락
- **persona 부여** — 특정 저자 정체성 지정

**커버 층위**: 어휘 ~ 담화 (얕게). 유일하게 구성 층위에 지시를 넣을 수 있는 값싼 방법 — "결론에서 요약하지 마라", "세 개씩 나열하지 마라" 같은 게 프롬프트로는 가능함

**비용**: 거의 0 | **한 달 완주**: 확실

---

## 2. 후편집 개입 (생성 후)

**작동**: 완성된 AI 글을 다시 씀.

**하위 종류**

- **문장 단위 paraphrase** — Russell 조건 3. 앞부분 문맥을 함께 넘겨 흐름 유지
- **전용 paraphrase 모델** — DIPPER (11B, 어휘 다양성·순서 재배열 제어)
- **토큰 치환** — HMGC. 각 토큰의 중요도 점수를 계산해서, 프록시 탐지기에 안 걸릴 때까지 마스크드 LM으로 동의어 교체
- **SFT 후편집 모델** — 너희 원래 방향 2. (AI 초안, 인간 수정문) 병렬 데이터 필요
- **반복 후처리** — Russell이 폐기. LLM 호출이 반복될수록 오히려 AI 특징이 더 붙음

**커버 층위**: 표면·어휘만. 문단 구성, 논지 순서, 인용 배치는 못 바꿈 — 바꾸려면 재생성이 됨

**비용**: 낮음~중간 | **한 달 완주**: 확실 (SFT 방식 제외)

---

## 3. 디코딩 개입 (생성 중)

**작동**: 토큰 선택 규칙을 바꿈. 모델 파라미터는 그대로.

**하위 종류**

- **샘플링 하이퍼파라미터** — temperature, top-p, repetition penalty. RAID가 이 정도 단순한 변화만으로도 탐지 성능이 크게 떨어진다고 보고. **공짜 baseline이라 반드시 대조군에 넣을 것**
- **Antislop Sampler** — 금지 문자열 발견 시 backtrack 후 재샘플링. 8천+ 패턴 억제
- **contrastive / proxy decoding** — 두 모델의 확률분포 차이로 선택. HUMPA가 이 계열의 정교한 버전
- **watermark 제거·역이용**

**커버 층위**: 어휘·n-gram. 문서 단위 구조는 시야 밖 (토큰 단위 결정이라)

**비용**: 낮음 (logits 접근 필요, 오픈웨이트만) | **한 달 완주**: 높음 (한국어 토크나이저 정렬이 변수)

---

## 4. 파라미터 개입 (모델 자체)

**작동**: 가중치를 바꿈. 추론 시 오버헤드 없음.

**하위 종류**

- **FTPO** — sampler backtrack 지점에서 자동 생성된 토큰 단위 preference pair로 학습. **데이터가 공짜**
- **문서 단위 DPO/ORPO** — chosen = 인간 글, rejected = AI 글. 구성 층위에 신호가 감. ORPO는 reference model 불필요라 메모리 절반
- **HUMPA** — 큰 모델을 안 건드리고 **작은 모델만 DPO로 학습해서 디코딩 시 큰 모델 확률을 덮어씀.** 평균 AUROC 70.4% 하락, 품질은 BERTScore 변화 0.02 이내. 프록시 공격이 직접 공격과 동등함을 이론적으로 보임
- **SFT on 인간 글** — 단순하지만 스타일 붕괴 위험

**커버 층위**: 학습 단위에 따라 다름. 토큰 단위면 어휘, 문서 단위면 구성까지

**비용**: 높음 (HUMPA는 작은 모델만 학습하므로 예외적으로 낮음) | **한 달 완주**: 낮음~중간

## 5. 데이터·목표 층위 (메타)

개입 지점이 아니라 **위 개입들의 신호원을 무엇으로 삼느냐**. 네 가정을 살리려면 여기가 실제 결정 지점임.

| 신호원 | 예 | 네 목표와의 정합 |
| --- | --- | --- |
| 탐지기 점수 | SICO, HUMPA, HMGC | **어긋남.** 기계를 속이도록 최적화됨 |
| 인간 글 분포 | Antislop (인간 corpus 대비 과다 표현) | 간접적. 사람 판단과 일치 보장 없음 |
| **사람 판정·설명** | Russell 가이드북 | **정합.** 근데 한 번만 받고 고정됨 |
| 사람 대리자 | Pangram 같은 강한 탐지기 | 정합할 수 있으나 상용이라 접근 불가 |

**여기가 기여 지점일 가능성이 큼.** 기존 방법 대부분이 탐지기 점수를 신호원으로 쓰는데, 네 가정이 맞다면 그건 잘못된 목적함수임. **사람 신호를 신호원으로 쓰는 방법은 Russell의 가이드북 한 번뿐이고, 그것도 프롬프트에 넣는 게 전부였음.** 사람 설명을 preference 데이터로 만들어 학습에 넣은 사례는 못 봤음.
