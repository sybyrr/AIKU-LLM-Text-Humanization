# 코퍼스 구조 · 용어 정의

> 대상: 국립국어원 신문 말뭉치 2023 (2022년 생산 기사)
> 파일럿 사본: HF 미러 `Saxo/ko-news-corpus-1~8`
> 상위: [프로젝트 개요](00-프로젝트-개요.md) · 관련: [러셀 평가방식](21-러셀-ACL2025-평가방식.md)
>
> 아래 수치는 모두 shard1(1,000,000행 / 103,464기사)에서 직접 확인한 값입니다.

---

## 1. ID 3층 구조

ID가 세 층 모두 숫자로 끝나서 `.1`, `.2` 같은 약칭을 쓰면 어느 층인지 알 수 없습니다.
**앞으로 `para_idx=1` 처럼 층을 명시해서 씁니다.**

| 우리 용어 | 필드 | 예 | 정의 |
| --- | --- | --- | --- |
| **파일** | `file_id` | `NIRW2300000001` | 매체 × 연도 단위 코퍼스 파일 |
| **기사** | `doc_id` | `NIRW2300000001.299` | 기사 1편. 이걸로 묶어야 기사 단위 |
| **문단** | `sentence_id` | `NIRW2300000001.299.4` | 기사 안의 문단 1개 |
| **문단 번호** | `para_idx` (파생) | `4` | `sentence_id`의 마지막 마디 |

`file_id` 접두어로 매체군이 갈립니다 — `NIRW` 인터넷신문, `NLRW` 지역지, `NWRW` 전국지.

## 2. 행의 단위는 문단입니다 (문장 아님)

컬럼명이 `sentence` / `sentence_id` 인데 **이름이 잘못 붙어 있습니다.** 실제 단위는 문단입니다.

| 근거 | 값 |
| --- | --- |
| 본문 행 중 문장 2개 이상을 담은 비율 | **29.1%** |
| 행당 평균 문장 수 | 1.4 |
| 행당 평균 길이 | 104자 |

실제 사례 — `NIRW2300000001.299.12` 한 행:

> 인터넷 포털사이트 오스템임플란트 종목 게시판도 '난리'가 났다. 개인투자자들은 "이런 거액을 횡령했는데 단독 범행이라니 말도 안된다"며 회사의 관리 소홀을 지적하거나, "날벼락을 맞은 것 같다"며 당황스러운 마음을 토로했다.

두 문장이 한 행에 있습니다. 원본 모두의 말뭉치의 `paragraph` 배열을 그대로 편 것으로 보입니다.

**따라서 기사를 복원할 때는 개행 2개로 join 해야 원문 문단 구조가 살아납니다.**
공백으로 이으면 문단 경계가 사라집니다.

## 3. `para_idx` 의 의미

| `para_idx` | 우리 용어 | 내용 |
| --- | --- | --- |
| `1` | **제목** | 기사 헤드라인. **본문이 아님** |
| `2` | **리드 문단** | 본문의 첫 문단. **부제가 아님** |
| `3` 이상 | **본문 문단** | |

`para_idx` 는 1부터 시작해 빈틈 없이 이어집니다 (103,464기사 전부 확인).
기사당 최대 `para_idx` 는 최소 2, 최대 49.

### 근거 — 위치별 특성

| `para_idx` | 평균 길이 | `~다.` 로 끝남 | 40자 미만 |
| --- | --- | --- | --- |
| 1 | 31.8자 | **3.6%** | **92.5%** |
| 2 | 76.0자 | 98.5% | 8.5% |
| 3 | 106.1자 | 99.4% | 1.3% |
| 4 | 108.8자 | 99.0% | 2.8% |

`para_idx=1` 만 제목 특성(짧고 서술문이 아님)이 뚜렷합니다. 마침표로 끝나는 비율은 0.01%.

`para_idx=2` 는 98.5%가 `~다.` 로 끝나는 76자짜리 서술문입니다. **부제가 아니라 본문 첫 문단이므로
러셀 프롬프트의 부제 자리에 넣으면 인간 산문이 유출됩니다.** 이 코퍼스에는 부제 필드도, 부제 자리도
없습니다. → [러셀 평가방식](21-러셀-ACL2025-평가방식.md)

## 4. 파이프라인에서 쓰는 파생 이름

`data/extract_russell_pool.sql` 이 쓰는 이름을 이 문서와 일치시켰습니다.

| 이름 | 정의 |
| --- | --- |
| `para_idx` | `sentence_id` 의 마지막 마디 (INT) |
| `title` | `para_idx = 1` 의 `sentence` |
| `body` | `para_idx >= 2` 를 개행 2개로 join (리드 문단 포함) |
| `n_para` | 본문 문단 수 = `max(para_idx) - 1` |
| `n_char` | `length(body)` |

## 5. 함정

- **`title` 컬럼을 쓰면 안 됩니다.** 값이 `노컷뉴스 2022년 기사` 같은 **파일 제목**입니다.
  기사 제목은 `para_idx = 1` 의 `sentence` 입니다.
- **HF 미러의 라이선스 표기 `apache-2.0` 은 업로더 오류로 보입니다.** 원자료는 모두의 말뭉치라
  재배포 금지 조건입니다. 파일럿에만 쓰고 논문은 정식 승인본 기준으로 갑니다.
- **`original_topic` 은 다중값이고 NULL 이 있습니다** (shard1에서 1,049기사). `경제>반도체`,
  `사회>사건_사고` 처럼 `대분류>소분류` 형식이고 콤마로 여러 개가 붙습니다. `_` 는 `/` 를 뜻합니다.

## 6. 정식 승인본 받으면 확인할 것

미러는 원본 JSON을 평탄화한 사본이라 **구조가 다를 수 있습니다.** 특히:

1. **제목이 어디 있는가** — 원본은 `document.metadata.title` 같은 메타 필드에 제목을 두고
   `paragraph` 배열에는 본문만 넣었을 가능성이 있습니다. 그렇다면 `para_idx = 1` 이 제목이
   아니게 되고 `n_para = max(para_idx) - 1` 도 틀립니다. **이 문서의 3절을 다시 검증해야 합니다.**
2. **미러가 버린 필드가 있는가** — 문서 단위 URL, 기사 유형, 추가 메타 등. 표본 추적에 쓸모가 있습니다.
3. 문단 경계가 원본과 동일한가.
