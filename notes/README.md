## 프로젝트 한 문단

LLM이 쓴 한국어 글은 특정 접속사·문구·문장 구조가 반복돼 상투적으로 느껴집니다. 영어권에는 이걸 줄이는 연구가 있지만 한국어는 조사·어미·띄어쓰기 변화가 많아 **문자열 기반 방법을 그대로 옮길 수 없고**, 기존 한국어 연구는 대부분 *탐지*에 몰려 있어 *생성 문체 개선*은 비어 있습니다. 이 프로젝트는 인간 글 ↔ AI 글 병렬 데이터를 만들고, 형태소 단위까지 고려한 방식으로 "AI 티"를 억제하는 것을 목표로 합니다.

## 30초 개념 요약

- **세 진영** — 공격(회피) / 방어(탐지) / 진단(측정). 우리는 주로 공격 + 진단.
- **개입 4단계** — 프롬프트 → 후편집 → 디코딩 → 파라미터. 뒤로 갈수록 비싸고 깊음. **문단 구성·논지 전개 층위는 파라미터 개입(문서 단위)이 아니면 못 건드림.**
- **평가 3축** — ① 여러 탐지기에서 TPR@고정FPR 하락 (최소 3종), ② 의미 보존, ③ 능력 유지. + 일반화와 방어책까지 내야 함.
- **핵심 긴장** — Russell 결과에 따르면 *사람*이 자동 탐지기보다 AI 글을 잘 잡습니다(전문가 다수결 TPR 99.3 / FPR 0). 그래서 "탐지기 점수를 낮추기"와 "사람을 속이기"는 같은 목표가 아닙니다.

## 열려 있는 쟁점

> 아래는 문서를 읽고 정리한 관찰입니다. 원본 노트에 이 형태로 적혀 있지는 않습니다.

1. **신호원 불일치.** [13-개입지점 §5](13-개입지점.md)는 "탐지기 점수를 신호원으로 쓰는 건 목적함수가 어긋난 것"이라고 결론냅니다. 반면 [30-MASH 제안](30-MASH-기반-제안.md)은 카피킬러 점수를 DPO reward로 씁니다. 두 문서가 서로 다른 목적함수를 전제하고 있어서, **어느 쪽을 프로젝트의 목표로 삼을지 아직 정해지지 않았습니다.** [13번 문서](13-개입지점.md)는 "사람 설명을 preference 데이터로 만든 사례가 없다"는 점을 기여 지점 후보로 지목합니다.
2. **도메인이 문서마다 다름.** 1차 회의록은 논증문·논문 초록·시(KatFishNet 도메인), [11-RQ](11-RQ.md)는 인터넷 기사, 2차 회의록 TODO는 한국어 기사. 확정 필요.
3. **카피킬러 제약.** API가 없어 보이고, 출력이 확률이 아니라 "AI 의심 어절 비율"입니다. MASH의 Inference-Time Refinement는 탐지기를 반복 호출해야 해서 그대로 적용이 어렵습니다.
4. **데이터 규모.** KatFishNet 인간 글은 약 470편, MASH는 6,000쌍을 씀. 코퍼스 후보는 [90-레퍼런스](90-레퍼런스.md) 하단 참고.
5. **`arxiv.org/pdf/2510.19492`가 어느 논문인지** 원본 노트에 명시돼 있지 않습니다 ([20-평가기준](20-평가기준.md) 축 1 각주).
