# 한국어 AI 문체 후편집 프로젝트 Handoff

최종 갱신: 2026-08-11

## 1. 한 줄 요약

한국어 AI 초안을 입력받아 **핵심 내용과 사실을 보존하면서 사람이 쓴 듯한 문체로 후편집하는 소형 모델**을 만듭니다. 주 방법론은 MASH의 `inverse data construction → style-injection SFT → detector-guided DPO`이며, 목표 black-box detector는 카피킬러입니다.

이 프로젝트는 논문 작성이 아니라 팀 프로젝트입니다. 새로운 언어학 이론을 만드는 것보다, 한국어에서 MASH의 핵심 가정과 파이프라인이 실제로 작동하는지를 재현 가능한 실험으로 보여주는 것이 우선입니다.

## 3. 확정된 목표와 비목표

### 목표

입력 AI 글 `x_ai`를 다음 조건을 만족하는 `x_humanized`로 변환합니다.

1. 주장, 사건, 수치, 고유명사, 인용 등 핵심 내용을 보존합니다.
2. 문법성과 유창성을 유지합니다.
3. 인간 평가에서 원본 AI 글보다 자연스럽다고 평가받습니다.
4. 카피킬러의 AI 작성 의심 비율도 감소합니다.

### 비목표

- KatFishNet 점수만 인간처럼 만드는 것이 목표가 아닙니다.
- 형태소·쉼표·띄어쓰기 규칙을 직접 설계하는 언어학 중심 접근은 핵심 방법이 아닙니다.
- GAN처럼 글쓰기 모델과 탐지기를 동시에 적대 학습하지 않습니다.
- 사람이 AI 글을 일일이 후편집하거나 preference pair를 직접 대량 작성하지 않습니다.
- 자체 binary detector를 학습 파이프라인의 reward/filter로 사용하지 않습니다.
- 카피킬러 점수 감소만으로 “인간다운 글 생성에 성공했다”고 결론짓지 않습니다.

## 4. 선택된 핵심 방법: 한국어 MASH

주 레퍼런스는 MASH입니다.

- 논문: `MASH: Evading Black-Box AI-Generated Text Detectors via Style Humanization`
- 게재: Findings of ACL 2026
- 로컬 PDF: `/Users/minjae/Downloads/MASH.pdf`
- 논문 페이지: https://aclanthology.org/2026.findings-acl.1487/
- 공개 코드: https://github.com/githigher/MASH

### 원 논문의 핵심 사실

- 인간이 AI 글을 수정한 pair 대신, **인간 글을 LLM이 다시 다듬은 역방향 pair**를 만듭니다.
- Stage 1 프롬프트는 “AI처럼 써라”가 아니라 문법·명료성·흐름을 개선하라는 일반적인 영어 교정 프롬프트입니다.
- 인간 원문은 detector가 인간으로 판정한 것만, LLM 교정문은 AI로 판정한 것만 남깁니다.
- Qwen2.5-3B-Instruct, Llama-3-8B-Instruct, GPT-2를 사용해 약 6,000개의 검증 pair를 만들었고, 인간→AI label-flip 비율은 약 95%였습니다.
- Essay, Reuters, WritingPrompts, STEM, Social Science, Humanity의 6개 도메인을 다뤘습니다.
- pair용 인간 원문은 Reuters에 `vblagoje/cc_news`, 나머지 도메인에 `dmitva/human_ai_generated_text`를 사용했습니다.
- 학습은 도메인별로 별도 수행했습니다. 한 모델에 모든 도메인을 섞는 구성이 기본이 아닙니다.
- 원 논문은 BART-base와 RTX 3090을 사용했으며, 도메인별 전체 학습 cycle을 약 7.5시간으로 보고했습니다.

### 이 방법의 정당화 수준

MASH는 “AI→인간 정답 pair는 비싸지만 인간→AI 변환은 자동화하기 쉽다”는 실용적 논리와 약 95% label flip으로 inverse construction을 정당화합니다. 그러나 다음은 직접 증명하지 않았습니다.

- pair가 실제로 내용은 완전히 동일하고 문체만 달라졌는지에 대한 강한 인간 검증
- 인간이 직접 후편집한 정답 pair와 inverse pair의 직접 비교
- 영어에서 성공한 inverse prompt가 한국어에서도 같은 방식으로 작동하는지

따라서 한국어 pilot은 선택 사항이 아니라 전체 프로젝트의 go/no-go 검증입니다.

## 5. 탐지기의 역할

### 카피킬러

카피킬러는 다음 두 역할을 가집니다.

1. MASH 데이터 생성 및 DPO용 target black-box detector
2. 최종 외부 평가 지표

주의할 점:

- 카피킬러 출력은 보정된 `AI일 확률`이 아니라 AI 작성 의심 문장·어절의 비율과 하이라이트입니다.
- 따라서 MASH의 `D(x) ∈ [0,1]`을 확률로 해석하지 말고, **동일 설정·유사 길이 안에서의 점수와 threshold**로 사용해야 합니다.
- threshold는 전역 상수가 아니라 도메인·길이별 인간 글 분포를 먼저 측정한 뒤 정합니다.
- 공식 API, 승인된 batch 처리 방식, 반복 호출 허용 범위가 아직 확인되지 않았습니다. 이용약관을 우회하는 scraping이나 rate-limit 회피는 구현하지 않습니다.
- 모두의 말뭉치·AIHub 글을 카피킬러에 업로드할 수 있는지도 데이터 이용약관상 별도로 확인해야 합니다.

### 자체 binary detector

AI 글과 사람 글을 학습한 별도 binary detector는 **분석 실험에만** 사용합니다.

- 후편집 전후 score 변화 분석
- 생성 모델·도메인별 효과 분석
- 카피킬러와 자체 detector의 판단 일치도 분석

이 detector는 pair 필터링, SFT, DPO, 최종 성공 판정에 사용하지 않습니다. 학습 데이터의 표면적 특징을 외우거나 새로운 생성 모델·도메인에 일반화하지 못할 가능성이 크기 때문입니다.

## 6. 후보 도메인과 권장 범위

사용자가 제시한 후보는 다음 세 가지입니다.

1. 논증문
2. 논문 초록
3. 시

현재 권장 순서는 **논증문 → 논문 초록 → 시**입니다.

- 논증문은 길이가 충분하고 주장·근거 보존을 평가하기 쉬워 첫 MVP에 적합합니다.
- 논문 초록은 목적·방법·결과·수치 보존 gate를 만들 수 있지만 사실 오류의 비용이 큽니다.
- 시는 짧은 글이 많고 행·연·이미지 보존이 중요합니다. 카피킬러의 300자 이하 결과도 불안정할 수 있어 별도 실험으로 취급하는 것이 안전합니다.

MASH가 도메인별 모델을 학습했으므로, 처음부터 세 도메인을 한 모델에 섞지 않습니다. 먼저 논증문 한 도메인에서 전체 pipeline을 검증한 뒤 같은 구조를 복제하는 편이 타당합니다. 시를 최종 범위에 유지할지는 아직 확정되지 않았습니다.

## 7. 전체 실행 순서

### Stage 0. 한국어 inverse construction pilot

학습 코드를 만들기 전에 다음 가정을 검증합니다.

1. 특정 도메인의 인간 원문을 수집합니다.
2. 카피킬러가 인간으로 안정적으로 판단하는 글만 남깁니다.
3. 한국어 LLM에 문법·명료성·흐름 개선을 요청합니다.
4. 교정문이 카피킬러에서 AI 쪽으로 실제 이동하는지 확인합니다.
5. 의미·사실 보존 gate를 통과하는 pair의 비율을 측정합니다.

권장 pilot 규모는 도메인당 50~100개입니다. 이는 논문의 요구량이 아니라 구현 여부를 결정하기 위한 최소 실험 제안입니다.

go 조건은 다음 세 조건이 동시에 관찰되는 것입니다.

- 인간 원문은 카피킬러 저점입니다.
- LLM 교정문은 카피킬러 점수가 일관되게 상승합니다.
- 핵심 명제·수치·인용·부정 표현은 보존됩니다.

label flip이 거의 없으면 MASH의 한국어 inverse construction 가정이 성립하지 않으므로, SFT 구현보다 먼저 프롬프트·생성 모델·도메인을 재검토합니다.

### Stage 1. 도메인별 pair 데이터 구축

데이터 흐름:

```text
인간 원문 x_h
  ├─ 카피킬러 인간 조건 통과
  └─ LLM 교정/재서술
        ├─ 카피킬러 AI 조건 통과
        ├─ 의미·사실 보존 gate 통과
        └─ 품질 gate 통과
              → (x_ai, x_h) pair
```

중요한 분할 원칙:

- 인간 원문을 먼저 train/dev/test로 나눈 뒤 LLM 교정문을 생성합니다.
- 같은 원문에서 파생된 텍스트가 여러 split에 들어가면 안 됩니다.
- URL, 문서 ID, 중복 문장을 기준으로 deduplication합니다.
- test에는 학습에 사용하지 않은 생성 모델의 교정문도 포함해 cross-generator 일반화를 봅니다.

권장 pair schema:

```json
{
  "pair_id": "...",
  "domain": "argument",
  "human_text": "...",
  "ai_text": "...",
  "source_corpus": "...",
  "source_document_id": "...",
  "generator_model": "...",
  "prompt_version": "...",
  "copykiller_human_score": 0.0,
  "copykiller_ai_score": 0.0,
  "semantic_score": 0.0,
  "preservation_checks": {},
  "split": "train"
}
```

논문의 약 6,000쌍은 6개 도메인 전체 규모입니다. 팀 프로젝트의 첫 목표는 한 도메인에서 500~1,000개의 **검증된** pair를 확보하는 것으로 잡을 수 있으나, 최종 수량은 Stage 0의 유효 pair 비율과 learning curve로 결정합니다.

### Stage 2. 한국어 Style-injection SFT

초기 backbone 후보는 SKT KoBART(약 124M)입니다.

- 기존 KoBART tokenizer와 embedding을 그대로 사용합니다.
- 형태소 tokenizer를 새로 학습해 교체하지 않습니다. pretrained embedding과 호환되지 않기 때문입니다.
- `x_ai`를 encoder에 넣어 content representation을 얻습니다.
- AI style embedding을 붙인 경로는 `x_ai`를 복원합니다.
- Human style embedding을 붙인 경로는 `x_h`를 생성합니다.
- 두 cross-entropy loss를 가중합합니다.

개념식:

```text
CR + ASR → fusion → decoder → x_ai 재구성 loss
CR + HSR → fusion → decoder → x_h 변환 loss
L_SFT = λ L_recon + (1-λ) L_trans
```

16GB GPU 기준으로 mixed precision, gradient accumulation, gradient checkpointing을 우선 적용합니다. KoBART 전체 fine-tuning이 가능한지 먼저 작은 batch로 메모리를 측정하고, 필요할 때만 LoRA를 검토합니다.

### Stage 3. Detector-guided DPO

MASH의 실제 preference 구성은 사람이 직접 고르는 방식이 아닙니다.

- prompt: Stage 1의 `x_ai`
- chosen: 대응하는 인간 원문 `x_h`
- rejected: Style-SFT가 human style로 생성했지만 카피킬러에서 아직 AI로 판단된 hard negative

카피킬러 score를 그대로 differentiable reward로 역전파하지 않습니다. score/threshold는 hard negative를 선택하는 데 사용하고, 이후 표준 DPO objective로 학습합니다.

hard negative가 의미 보존 gate를 통과하지 못하면 DPO 데이터에 넣지 않습니다. 그렇지 않으면 모델이 띄어쓰기 훼손, 문장 삭제, 길이 축소 같은 detector exploit을 배울 수 있습니다.

### Stage 4. 선택적 inference-time refinement

MASH의 Stage 4는 DPO 후 발생한 문법·유창성 저하를 복구하는 선택적 단계입니다. MVP에 반드시 필요한 단계는 아닙니다.

구현한다면 다음을 바꿔야 합니다.

- 영어 정규식 sentence split → Kiwi `split_into_sents` 또는 KSS
- 공백 기준 word count → 한국어 문장/형태소 기반 길이 처리
- 문장을 `" ".join(...)`으로 재조립하지 않고 원래 offset·문단·개행 보존
- 시는 문장 대신 행·연 단위 처리
- 영어 Pythia perplexity → 고정된 한국어 causal LM 기반 PPL
- 후보 교체 전 의미·사실 보존 gate와 카피킬러 판정 모두 확인

## 8. 한국어 적용 시 필요한 변경

MASH의 pair 구성, style embedding, SFT/DPO 수식 자체는 언어 독립적입니다. 형태소 특징을 직접 설계할 필요는 없습니다. 다만 다음 의미 보존 지점은 반드시 검사해야 합니다.

- 조사 변경으로 주체·객체가 바뀌는 문제
- 연결·종결 어미 변경으로 시제·인과·추정·확신도가 바뀌는 문제
- 부정 표현의 누락 또는 범위 변경
- 높임법과 문체 수준의 불일치
- 띄어쓰기 변화에 따른 Copykiller 점수 exploit
- 주어 생략 때문에 생기는 지시 대상 변화
- 문장 분리 시 인용·괄호·목록·개행 훼손

도메인별 보존 gate:

- 논증문: 중심 주장, 근거, 반론, 결론, 인과관계
- 논문 초록: 연구 목적, 방법, 데이터, 수치, 결과, 한계, 인용
- 시: 행·연, 화자, 핵심 이미지, 반복 표현, 의도적인 비문과 띄어쓰기

어떤 코퍼스든 다운로드·재배포·외부 서비스 업로드 허용 범위를 먼저 확인합니다. 학교 계정으로 카피킬러를 사용할 수 있다는 사실은 코퍼스를 제3자 서비스에 업로드할 권한까지 보장하지 않습니다.

## 10. 평가 설계

### 비교할 시스템

1. 원본 AI 초안
2. 일반 프롬프트 기반 후편집
3. Style-SFT
4. Style-SFT + DPO
5. Style-SFT + DPO + refinement(구현한 경우)

### 핵심 평가 축

- **인간다움:** blind human preference와 자연스러움 평정
- **내용 보존:** 핵심 명제·수치·고유명사·인용·부정 보존
- **품질:** 문법성, 유창성, 논리적 응집성
- **탐지 결과:** 카피킬러 의심 비율과 의심 구간 변화
- **일반화:** 미사용 주제·생성 모델에서의 성능

한국어 BERTScore 또는 KLUE STS 계열 encoder는 보조 의미 유사도 지표로 사용할 수 있지만, 수치·부정·인과관계 보존을 보장하지 않습니다. 구조화된 보존 검사와 일부 인간 검증을 함께 사용합니다.

카피킬러의 한 threshold에서 accuracy만 보고하지 않습니다. 후편집 전후 paired score 변화, 통과율, 길이별 결과를 함께 봅니다. 300자 이하 표본은 별도 집계합니다.

### 성공을 주장할 수 있는 최소 조건

- 원본 AI 초안과 prompt-only baseline보다 인간 평가가 개선됩니다.
- 카피킬러 의심 비율도 감소합니다.
- 핵심 내용과 사실 보존은 사전에 정한 허용 수준 아래로 악화되지 않습니다.
- 한 생성 모델에서만 성공한 것이 아니라 최소 한 개의 미사용 생성 모델에서도 효과가 재현됩니다.

## 11. 가장 중요한 위험과 대응

1. **Copykiller 연동 불가:** 공식·승인된 자동 접근이 없으면 대규모 Stage 1/DPO 구축이 병목입니다. 먼저 접근 가능성과 이용 조건을 확인하며, 불가능할 경우 임의 scraping으로 대체하지 않습니다.
2. **inverse pair 가정 실패:** 한국어 LLM 교정문이 카피킬러에서 AI 쪽으로 이동하지 않으면 MASH를 그대로 적용할 근거가 없습니다. Stage 0에서 조기 판정합니다.
3. **detector gaming:** 점수는 낮아졌지만 오류가 늘 수 있습니다. DPO 전에 의미·품질 gate를 적용하고 인간 평가를 최종 기준으로 둡니다.
4. **도메인 mismatch:** MASH도 Reuters에는 별도 `cc_news`를 사용했고 generic corpus의 transfer가 실패했습니다. 각 도메인과 가까운 인간 corpus를 사용합니다.
5. **시의 특수성:** 짧은 길이와 자유로운 문법 때문에 다른 두 도메인과 같은 전처리·평가를 적용하지 않습니다.

## 12. 미확정 사항

다음은 구현 전에 확정하거나 pilot에서 결정해야 합니다.

- 최종 도메인에 시를 포함할지
- 사용할 인간 코퍼스와 외부 서비스 업로드 허가
- 카피킬러의 공식 자동화 수단, query 한도, score 재현성
- 도메인·길이별 threshold 정의
- inverse pair 생성 LLM과 한국어 프롬프트
- KoBART를 최종 backbone으로 사용할지
- 목표 pair 수와 최대 sequence length
- 의미 보존 gate의 구체 모델·임계값
- Stage 4 refinement의 MVP 포함 여부
- 인간 평가 문항, 표본 수, 성공 기준

## 13. 다른 에이전트가 가장 먼저 할 일

1. 카피킬러 접근 방식과 데이터 업로드 허용 범위를 문서로 확인합니다.
2. 논증문 인간 글 50~100개로 Stage 0 pilot 데이터 schema와 실행 스크립트를 만듭니다.
3. 최소 2개의 한국어 LLM·프롬프트 변형으로 교정문을 생성합니다.
4. Copykiller score 변화와 의미·사실 보존 통계를 내어 go/no-go를 결정합니다.
5. go 이후에만 MASH 공개 코드에서 Stage 2 구조를 KoBART로 포팅합니다.

## 16. 핵심 판단 기준

이 프로젝트에서 가장 먼저 답해야 할 질문은 “KoBART를 어떻게 학습할까?”가 아닙니다.

> **한국어 인간 글을 LLM이 일반적으로 교정했을 때, 내용은 유지되면서 카피킬러가 인식하는 AI 문체가 실제로 주입되는가?**

이 가정이 pilot에서 성립하면 MASH의 자동 pair construction과 Style-SFT/DPO가 현실적인 선택입니다. 성립하지 않으면 대규모 학습 전에 방법론을 바꿔야 합니다.
