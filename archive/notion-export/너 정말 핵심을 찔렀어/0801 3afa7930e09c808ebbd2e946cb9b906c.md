# 0801

### 기여 가능한 자리 — 전체

이 분야는 **공격(회피) / 방어(탐지) / 진단(측정)** 세 진영이 있고, 각각에 여러 자리가 있음.

**공격 쪽**

- **A1. 생성 시점 개입** — sampler, 디코딩 조작. 학습 없음
- **A2. post-training으로 모델 자체를 바꿈** — FTPO, DPO/ORPO. "AI 티 안 나게 쓰는 한국어 모델"을 만드는 것. 네가 말한 그거. 기여 크고, GPU와 preference 데이터가 듦
- **A3. 후편집** — AI 초안을 다시 쓰는 별도 모델. DIPPER 계열. 병렬 데이터 필요
- **A4. 프롬프트/컨텍스트 개입** — persona, few-shot 인간 예시. 제일 싸고, 놀랍게도 baseline으로 강함

**방어 쪽**

- **D1. 더 나은 한국어 탐지기** — KatFishNet은 띄어쓰기·품사·쉼표라는 얕은 통계 feature 기반이라, 형태론적 feature를 더 넣거나 Binoculars 같은 likelihood-ratio 계열을 한국어로 옮기면 개선 여지가 있음. **정공법이고 기여가 명확함** [ACL Anthology](https://aclanthology.org/2025.acl-long.1030/)
- **D2. 공격에 강건한 탐지기** — 회피 시도를 뚫는 쪽. RAID가 보여준 게 단순한 변화(샘플링 전략 변경, 반복 페널티)만으로도 탐지 성능이 크게 떨어진다는 거라, 여기가 실제로 열려 있음 [arXiv](https://arxiv.org/abs/2405.07940)
- **D3. 탐지기 자체를 평가/감사** — 한국어 탐지기의 오탐(비원어민, 특정 문체를 AI로 오판)을 측정. 사회적 임팩트 크고 계산 싸고, 네 평가 연구 경험이랑 제일 잘 붙음

**진단 쪽**

- **G1. 한국어 slop 프로파일** — 뭐가 AI 티인지 목록화. 내가 계속 밀던 것
- **G2. 관측자 간 해리 측정** — 기계 난이도 vs 사람 난이도. 아까 나온 숫자
- **G3. 층위 분해** — AI 티가 형태·어휘·담화 중 어디서 오나

**메타**

- **M1. 벤치마크/데이터셋 구축** — 한국어 humanized text 벤치마크. 인용 많이 되지만 노동 집약
- **M2. 공격-방어 공동 평가** — 둘을 붙여놓고 어느 지점에서 균형이 잡히는지
